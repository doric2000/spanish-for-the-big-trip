# ספרדית לטיול הגדול

**לומדים מה שצריך לטיול, בתרגולים קצרים וממוקדים.**

אפליקציה לדוברי עברית שרוצים להבין ולענות בספרדית במצבים מעשיים בטיול. דור ו־Codex מפתחים אותה יחד, עם השתתפות מעשית של דור והסבר של כל שלב. דרך העבודה נמצאת ב־[DEVELOPMENT_GUIDE.md](DEVELOPMENT_GUIDE.md).

## מצב נוכחי

שלב 01: סביבת עבודה והרצה ראשונה באייפון. דור יצר את תיקיית הקוד ואתחל מאגר Git מקומי בענף `main`. התוצר הנוכחי הוא מאגר עם מסמכי בסיס וכללי התעלמות מקבצים; הפעולה הבאה היא סקירתם, שמירת commit ראשון ולאחר מכן הקמת אפליקציית Expo קטנה.

דור בדק ב־PowerShell את הכלים הבאים ב־14 באוקטובר 2026:

| כלי | גרסה שדור דיווח |
| --- | --- |
| Node.js | 22.23.1 |
| npm | 10.9.8 |
| Git | 2.45.1.windows.1 |

דור דיווח גם על כניסה מוצלחת לחשבונות Apple Developer ו־Expo, מנוי Apple פעיל וגישה ל־Certificates, Identifiers & Profiles. חתימה, בנייה בענן והרצה באייפון ייבדקו בהמשך שלב 01. יש לתעד את הצלחת האפליקציה ואת התקדמות הלמידה בנפרד.

## מבנה המאגר

קובצי הבסיס שנוצרו:

- `AGENTS.md`: הוראות העבודה לסוכנים בשורש Git.
- `DEVELOPMENT_GUIDE.md`: מחזור העבודה והלמידה המשותפת.
- `.gitignore`: כללים לקבצים מקומיים ולתוצרים שאינם נשמרים בהיסטוריית Git.
- `README.md`: נקודת הכניסה לפרויקט.

התיקיות המתוכננות יתווספו כשהשלב הרלוונטי מתחיל:

```text
spanish-for-the-big-trip/
├── apps/
│   ├── mobile/      React Native, Expo ו־TypeScript
│   └── api/         Node.js ו־NestJS
└── supabase/        שינויי מסד הנתונים ב־SQL
```

האפליקציה והשרת יישמרו במאגר אחד. לכל יישום תהיה התצורה הדרושה לו. קוד משותף ומערכת לניהול חבילות במאגר ייבחרו רק כשיהיה בהם צורך. `package-lock.json` יישמר ב־Git כשנשתמש ב־npm להתקנת התלויות, כדי לתעד את הגרסאות שנבחרו.

## היקף הגרסה הראשונה

נבחרו TypeScript, React Native עם Expo, Node.js עם NestJS ו־PostgreSQL ב־Supabase. היעד הוא יחידה 1A מלאה באייפון עם Google ו־Apple לכניסה, שמע בספרדית, תרגול, סימולציה מוכנה, שמירה וחזרה, הקלטה להשמעה עצמית ומפה קטנה. תוכן היחידה והשמע ייבדקו עם דור, שלב אחד בכל פעם. אירוח ה־API ייבחר בשלב הפריסה.

## עבודה עם Git

המאגר המקומי נמצא ב־`C:\Users\doric\Documents\SpanishForTrip\spanish-for-the-big-trip`. נשתמש ב־`main` בתחילת העבודה ונשמור שינויים קטנים שנבדקו יחד. Commit הוא נקודת היסטוריה של קבצים שנבחרו לשמירה, עם הודעה שמסבירה את השינוי.

לבדיקת מצב הקבצים מתוך תיקיית המאגר:

```powershell
git status --short
```

`??` מציין קובץ חדש ש־Git עדיין אינו עוקב אחריו. נסקור את הקבצים לפני בחירתם ל־commit הראשון. כלל ב־`.gitignore` מונע הוספה אוטומטית של קבצים מתאימים שאינם במעקב; הוא אינו מוחק קבצים מהמחשב ואינו מוציא מההיסטוריה קובץ שכבר נשמר.
