# בדיקת הקלטה והשמעה — שלב 01

Codex כתב את הקוד לפי חלוקת העבודה ב־[מדריך הפיתוח](../DEVELOPMENT_GUIDE.md). דור התקין את החבילות ובודק את התוצאה באייפון. זו בדיקת יכולת ראשונית; תוכן יחידה 1A עדיין נכתב ונבדק יחד בהמשך התכנית.

## הרצה ובדיקת מכשיר

מתוך תיקיית `mobile/` ב־PowerShell מריצים:

```powershell
npm.cmd start -- --go
```

`npm` מפעיל את סקריפט `start` שב־`package.json`. הסימן `--` מעביר את הארגומנט `--go` ל־Expo, כדי לפתוח דרך Expo Go גם כשהחבילה `expo-dev-client` מותקנת. אם שרת קודם פועל באותו טרמינל, עוצרים אותו עם `Ctrl+C` לפני ההרצה. סורקים את קוד ה־QR באייפון. Reload ידני הוא דרך העדכון שנבחרה כרגע.

בדיקה ראשונה של דור: לחיצה על ״להקליט את עצמי״, אישור הרשאת המיקרופון אם התבקשה, אמירת משפט קצר, לחיצה על ״עצירת הקלטה״ ועל ״השמעת ההקלטה״. הצלחה היא שמיעת ההקלטה בפועל. לאחר מכן אפשר לבדוק השמעה חוזרת, הקלטה נוספת וסירוב הרשאה בנקודת בדיקה מתאימה. אין להסיק הצלחת מיקרופון או שמע מבדיקת TypeScript בלבד.

## קריאת הקוד

המסך וכל ההתנהגות נמצאים ב־[App.tsx](App.tsx):

- `useState` שומר מידע שמשנה את המסך: כתובת ההקלטה האחרונה והאם פעולה עדיין מתבצעת. שמירת מידע חדש גורמת ל־React לעדכן את התצוגה.
- `useAudioRecorder` יוצר מקליט שמנוהל לאורך חיי המסך. `useAudioRecorderState` מעדכן את מצב ההקלטה ואת משכה. עדכון סיום/כשל מאפשר להציג הקלטה שהסתיימה או הודעת שגיאה.
- `toggleRecording` מחובר ללחיצה דרך `onPress`: הוא מבקש הרשאה, מכין את המקליט ומתחיל להקליט, או עוצר ושומר את כתובת הקובץ. `await` ממתין לסיום פעולה כמו בקשת הרשאה בלי לחסום את ממשק האפליקציה.
- `useAudioPlayer` יוצר נגן אחד קבוע. האפשרות `keepAudioSessionActive` מונעת מ־pause של הנגן לכבות באיחור את מערכת השמע בזמן שהמקליט מתחיל לפעול. `togglePlayback` מעביר את השמע למצב השמעה, מחזיר את המיקום להתחלה ומשמיע; לחיצה בזמן השמעה עוצרת אותה.
- עצירת המקליט והשלמת כתיבת הקובץ הן שני אירועים שונים ב־iOS. הקוד ממתין גם ל־`stop()` וגם לאירוע `isFinished` לפני `player.replace` עם הקובץ המוכן. מגבלת זמן משחררת את הכפתורים ומציגה שגיאה אם אישור הסיום לא מגיע. בכל הקלטה נוצר קובץ חדש כדי למנוע שימוש חוזר בקובץ קודם ב־SDK57.
- `isBusy` משבית כפתורים בזמן פעולה. `actionInProgress` הוא `ref`: ערך שמתעדכן מיד ומונע שתי פעולות חופפות גם לפני ש־React מספיק לצייר מחדש.
- לחיצה על הקלטה חדשה עוצרת השמעה קיימת. כפתור ההשמעה זמין רק כשיש הקלטה טעונה וכשהמקליט אינו פועל. `try/catch` מציג משוב כשפעולה נכשלת; סירוב הרשאה מקבל הודעה מתאימה ואפשרות לפתיחת הגדרות כשנדרשת.

קובץ ההקלטה נשמר במטמון המקומי. ההפניה אליו נשמרת בזיכרון המסך; לאחר Reload אין שחזור אוטומטי. מערכת ההפעלה רשאית למחוק קובצי מטמון. אין בקוד העלאה או שמירה של ההקלטה בענן.

ב־[app.json](app.json) מוגדרים נוסח הרשאת מיקרופון בעברית וכיבוי יכולות שמע ברקע עבור הבנייה העצמאית. Expo Go משתמש בהרשאות של עצמו; הנוסח שלנו ייבדק בבנייה משלנו. הבדיקה הנוכחית מיועדת כשהאפליקציה פתוחה בחזית.

ה־API מבוסס על [תיעוד expo-audio ל־SDK57](https://docs.expo.dev/versions/v57.0.0/sdk/audio/). חתימה, בנייה והתקנה עצמאית עדיין נדרשות להשלמת שלב 01.

## תוצאת הבדיקה והמשך האבחון

דור דיווח ב־15 באוקטובר שממשק ההקלטה פועל, אך ההשמעה מוצגת לרגע קצר ואין קול. Codex תיקן את תזמון מערכת השמע ואת ההמתנה לסיום הקובץ והוסיף הצגת משך ההקלטה ושגיאות נגן. לאחר בקשת הבדיקה החוזרת דור אישר ״עובד״: התקבל אישור משתמש להקלטה ולהשמעה בפועל באייפון דרך Expo Go. לא נמסר אורך מדויק של הקובץ, ולא נבדקו בנפרד כל מקרי הסירוב וההפרעות. המימוש של Codex והבדיקה של דור מתועדים בנפרד ביומן הלמידה. בנייה והתקנה של אפליקציה משלנו עדיין נדרשות.

בדיקות רצף פעולות פועלות על הפונקציות האמיתיות של `App.tsx` מול ממשקי מכשיר מדומים, ללא התקנת ספריית בדיקות:

```powershell
node --test tests/audio-flow.test.cjs
```

שלוש הבדיקות מאמתות שמירת מערכת השמע בזמן הקלטה, המתנה לאירוע השלמת הקובץ ושחרור כפתורים במקרה של היעדר אירוע. בדיקת TypeScript עברה גם אחרי התיקון. הבדיקות אינן מאמתות הקלטה או שמע בחומרת האייפון.
